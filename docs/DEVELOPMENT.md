# Sclerite Studio · 开发与历史验证记录

面向八放珊瑚骨针光镜照片的本地桌面软件。0.12.3 提供两个功能选项卡：**图像处理 / 分类**。原有测量、完整确认和联合排版保持独立。

## 0.12.3 中英文界面 / Bilingual interface

- 首次启动默认中文，不跟随系统语言。主界面和排版页右上角可切换 **中文 / English**；选择仅保存在本机，重启后沿用。无法访问本地存储时仍可在当前会话切换。
- 图像处理、完整性复核、分类、排版、帮助、工具提示及应用自身的错误/进度信息提供中英文。操作系统、第三方库的原始诊断保持原样，便于排错。
- 切换不重载工作区，不改变分割、确认、选择、版面、训练参数或模型缓存。照片名、标本编号、人工类别、形态备注、图版标签等用户内容不自动翻译。旧项目中的组织选项保留原始值，仅翻译其显示名称。
- 界面翻译集中在 `src/i18n-en.json` 与 `src/i18n-native.json`；`src/i18n.ts` 负责本地语言选择、参数插值和旧版原生消息适配。不要把用户填写的名称传入翻译函数。项目/CSV/模型的数据字段、历史研究说明文档及许可文件不因界面语言而改写。
- 验证：`npm test`；开发预览运行时执行 `node tests/i18n.smoke.mjs`。后者使用 MR0145 的真实照片检查默认语言、语言记忆、数据保留及 1040 / 1440 像素布局。

The app starts in Chinese. Choose **English** at the top right of the main workspace or plate editor; your choice is remembered locally. Switching language preserves the workspace and model data. User-authored specimen IDs, class names, notes and labels are never translated. Project schemas, CSV fields, historical research documents and licenses remain unchanged.

## 0.12.3 DINOv3 本地分类

- 随本轮 Mac DINOv3 发行包提供可运行的 ViT-S/16 LVD-1689M 冻结编码器，384 维 CLS 特征；在“分类 → 训练与验证设置 → 特征模型”选择。默认仍为 MobileNetV4，不擅自替换已有模型。
- 使用用户提供的 Meta 原始权重，SHA-256 为 `08c60483bc63c04f533611e34bf70b120eedb7240f469bc16e9e20bf344b941d`。官方实现固定于 `6876159a11b4df116f30f667f8c9888617df0751`，安全加载纯权重并严格匹配所有参数；转换不修改原文件，不保存邮件下载凭证。
- 输入仍为 Rust 统一 mask/灰底/保比例 256×256 预处理，输出 L2 归一化；冻结编码器，只训练轻量逻辑回归。两种编码器的缓存和分类器分开，切换不改人工标签或划分。
- DINOv3 当前仅开放 CPU；选择时自动切到 CPU，禁用未验证的 Core ML 路径。MobileNet 的 CPU/Core ML 功能保留，不使用 NPU。
- 13 枚真实裁剪的官方 PyTorch/ONNX Runtime 特征最大归一化差为 2.48×10⁻⁶ 以下；原生 Rust 与 Python 同版本 ONNX Runtime 参考特征一致。原生训练、导出、导入和缓存命中已通过。没有宣称 DINOv3 在骨针上比 MobileNet 更准确。
- 完整 DINOv3 许可随应用资源及导出模型包提供。旧发行包保留，详情见上级 `分类功能-0.12.3说明.md`。

含 DINOv3 的 Apple Silicon 构建（macOS 14+）：

```sh
npm run desktop:build -- --features dinov3 --config src-tauri/tauri.macos-dinov3.conf.json --bundles app
```

默认不加 feature 的源码构建仍不包含 DINOv3，以保留轻量构建及无权重环境兼容性。开发端可用 `scripts/export_dinov3.py --checkpoint /path/to/weights.pth --meta-repo /path/to/pinned/dinov3 --license /path/to/pinned/dinov3/LICENSE.md --tensors /path/to/qa` 重现转换；输出已存在时拒绝覆盖。Python 只用于开发转换和参考测试，不随应用运行。

## 0.12.2 特征准备与轻量训练

- “准备特征”独立于人工标签：完整确认的骨针可先提取特征，再标注、训练；改类别名称、标签或分区复用磁盘特征，不重复运行编码器。原图、mask、预处理、编码器权重或计算后端变化会重新计算。界面数量是本次已核验的缓存，不是未经检查的磁盘库存。
- 冻结 MobileNetV4，只训练轻量逻辑回归。正式评估可在 λ=0.01、0.001、0.0001 中按验证集 Macro-F1 选择；同分优先较强正则。未收敛候选不参与选择。测试集只用于选择完成后的报告，不用于选参数；试用模式固定 λ=0.001。
- 按编码器与任务分别保存分类器；模型包记录正则候选、验证成绩和最终选择。旧 MobileNet 缓存、旧模型包仍可读取。
- DINOv3 ViT-S/16 的编码器接口、384 维分类层与受控导出流程已接入，但本版**未随附 DINOv3 权重，不可选用**。需要用户合法取得本地检查点和许可后，开发端运行 `scripts/export_dinov3.py`，至少用 5 枚真实骨针裁剪验证 PyTorch/ONNX Runtime 1.24.2 CPU 一致性；验证清单与权重哈希通过后才允许 `--features dinov3` 构建。DINOv3 Core ML 尚未验证，暂不开放。
- 不增加 Python 用户依赖、服务器、模型商店、降维图或新的功能页；不启用 NPU。分割和排版逻辑保持原状。

## 0.12.1 训练前准备

- 人工标注支持最近 20 步撤销/重做，包括批量确认、清除和接受建议；快捷键 Command/Ctrl Z、Command/Ctrl Shift Z（Windows 也支持 Ctrl Y）。只恢复人工字段，保留已有预测。轮廓、完整确认或照片集合变化后清空历史；历史不写入项目，但最终标签正常保存。
- 点击训练先打开一页检查：类别、骨针、标本、独立组、重复原图、未标注对象和分区限制。浏览器也可查看检查，桌面版检查通过后才可训练。小样本无法按 60/20/20 覆盖类别时尝试约三等分，绝不拆分标本组。
- 模型保存 SHA256 训练数据快照；标签、类别、标本、轮廓或分区变化后提示过期。撤销恢复原标签后可重新匹配，预测和排版不触发过期。外部模型与没有快照的旧模型分别说明，不伪装为最新模型。过期不会自动重训或禁止预测。
- 模型与分割参数均未调整。快照用于项目一致性检查，不是独立验证、签名认证或防篡改保证。

## 0.12 分类

顶部第二个选项卡“分类”替代旧研究入口。标签与预测随项目、自动恢复副本保存；旧项目元数据继续保留。新项目请使用 0.12 或更高版本打开。

- 在处理页勾选完整骨针；分类页建立形态类型或已知物种类别，按住 Command / Ctrl 点击多选，或“全选列表”后批量确认类别。
- 逐张照片指定独立标本。显示名和 UUID 分开，不从照片文件名推断个体。同一标本的多个视野必须选择同一标本。
- MobileNetV4-Conv-Small 冻结编码器，实际去掉分类层后的输出为 **1280 维**（960 是骨干特征图通道数，不是最终向量维度）。原图二值 mask 裁剪、5% 边距、灰底保比例 256×256；Rust 统一预处理，L2 归一化。
- 类别和标本均衡的多类逻辑回归；自包含 L-BFGS、λ=0.001、FP64 优化、FP32 权重保存。没有用户端 Python、训练服务器或 NPU。
- 默认试用模型不展示独立泛化成绩。可启用按独立标本／群体分组评估；固定种子 20260922，目标 60/20/20，以组完整性和类别覆盖优先。不足时阻止正式评估，不退回骨针随机划分。已有分区和锁定测试集不能转入训练。
- 训练自动保存当前模型；加载／导出包含编码器、类别顺序、轻量分类层、预处理版本、训练清单、评估和许可的完整 ZIP。仅接受与内置编码器哈希一致的模型，不运行外部自定义算子。
- 模型建议与人工标签分开，预测不会覆盖人工类别。只有“接受选中建议”才写入人工标签。旧模型建议有明确提示；重分割和轮廓改变后的旧标签不进入训练。
- 分类结果可导出 CSV。试用模型不等于物种识别已验证，更不是自动物种界定。
- 首版仍为每工作空间 30 张照片；训练面向自采光镜，不混合论文 plate。重复原图按 SHA256 分组；重新编码、重拍和重复骨针仍需人工审查。

Mac Apple Silicon 版随附微软官方 ONNX Runtime 1.24.2，要求 macOS 14+。默认 CPU，可选 Core ML CPU/GPU（不启用 Neural Engine）。Windows 代码保留 CPU 后端；本轮没有 Windows 实机验收。旧的 0.11 发行包未恢复。

## 0.7 原始尺寸与联合排版

- 不再逐枚放大填满格子。未校准照片默认按原始像素比例摆放，2400×1800 PNG中通常1个原图像素对应1个导出像素；过大的对象仅触发同单位组整体等比例缩小，右侧显示实际导出/原图像素比例。
- 校准照片按共同物理倍率摆放，以首张已校准照片的原像素倍率为参考。不能同时保持不同拍摄倍率照片的原像素1:1和真实物理尺寸可比；默认选择后者。未校准照片另页处理，px不能作为实际长度。
- 可选择参与照片。按来源分组排版便于追溯；取消“按照片分组”启用空闲矩形紧凑装箱，让小对象利用大对象旁的空隙。大小不变，容量不足自动分页。此为启发式排版，不宣称全局最优。
- 统一倍率页面使用共用标尺；逐枚手动缩放后，各自标尺随实际倍率重算。只有已校准对象才显示μm，其他显示px。可隐藏标尺。
- A-1、B-5等编号对应来源照片和原实例编号。页脚保留来源；“导出全部页”输出每页PNG及sources.json（全部来源、尺寸、标尺数值），单页PNG按钮只导出当前页。
- 页码、尺寸、背景、角度、分组和标尺设置随项目、版面JSON和恢复副本保存。原始图像/mask/测量不因排版改变；重复视野中的相同骨针不会自动识别或去重，请人工排除。

## 0.6 排版改进

- 默认“载入时自动转正”：从透明mask的二阶中心矩估计几何长轴，竖直排列；不按内部明暗取向，不改变原始裁剪、mask或测量值。近等轴形状（主轴强度小于0.12）不强行定向；不推断头尾。
- “全部沿长轴转正”重新排列全版；“选中转正”处理选中对象并尽量保留位置。仍可逐枚拖动、旋转滑杆/输入角度、翻转180°和缩放。普通“自动排版”保留当前手调角度。
- 旋转后的占用范围用于网格适配和页边约束；标签始终水平置于图像下方。
- 黑底/白底选择同步预览及2400×1800 PNG，标签自动使用反差色。背景和角度保存在独立JSON、项目ZIP及本地恢复副本中。旧版JSON默认白底；点击转正可从已有透明裁剪补算长轴。
- 修复拖动时DOMPoint坐标提取问题，防止移动后出现无效位置与导出裁切。

## 0.5 工作台改进

- 顶部压缩为工具栏；图像列表、处理设置可折叠，小窗口默认收起图像列表；拖动测量表上沿调整高度，最右勾选列固定可见。
- 点击行或缩略图放大定位；表格获得焦点后，↑/↓选择，空格确认并前往下一枚。输入框、按钮和对话框中不会触发这些快捷键。可筛选全部、待复核、已确认或自动切分对象。
- “自动切分”是来源，不是确认状态。选中切分对象显示原图与边界对照；“撤销本组切分”保持原前景像素和其他组确认，仅清除该组确认与备注，可撤销恢复。
- 高级参数默认折叠，运行按钮常驻底部。修改参数后会明确提示结果尚未更新；重新分割仍需确认，避免覆盖手工修正。旧项目未记录参数来源时提示来源未知。
- 普通提示放在底部状态栏，不遮挡原图或勾选框；完整提示可悬停查看。

不需要账号、服务器、Python或独立显卡；图像不会上传。内置示例是明确标注的合成图，不是科研样本。

## 使用

1. 导入PNG、JPEG或单页TIFF；也可以拖入图像，或点击“体验合成示例”。
2. 点击“校准”，沿图中的已知比例尺拖线，输入实际长度，单位μm。没有可靠比例尺时保持像素单位，不能推测实际尺寸。
3. 明背景通常选择“深色骨针”；暗背景选择“亮色骨针”。运行自动分割。背景不均时调节背景校正半径；均匀背景可设为0。校正窗口应大于目标横向尺寸。
4. 默认排除贴边、角落标注和低对比对象，并启用自动切分接触组合。使用0.30切分保守度、0.25最小内核比例，子对象最小面积1500 px²；长宽比>3不自动切。参数基于MR0145样例选择，不保证其他图像最佳。旧项目保留旧mask且默认不新启用自动切分；需勾选“自动切分接触组合”再运行。
5. 在“候选测量”表格的“状态”右侧勾选确认。自动分水岭仅重新分配可见像素，不补画遮挡，切线未必是真实边界。漏切可手动切开，误切可Shift多选后合并，或撤销后调高保守度重跑。遮挡和破损对象仍需删除。任何mask修改清空该图确认状态，撤销恢复先前状态。CSV的review_hint与auto_split_parent、项目splitEvents保留自动切分来源；手工编辑后自动切分记录清空，避免错误归属。
6. “导出结果”及CSV只输出已确认完整实例，包括mask、crop、透明图和测量表；“保存项目”保留全部待复核候选和排除原因。两者都能通过“打开项目”恢复。结果导出不会替代完整工作项目保存。

**退出前保存项目（包含版面）。**停止修改约3秒后自动更新本机IndexedDB恢复副本，启动时询问是否恢复；不包含撤销历史，不是正式文件备份，也不跨设备。容量或权限失败会在状态栏提示。只保留最近一份；暂不恢复后开始新工作会替换该副本。窗口关闭提示是辅助保护。批处理按每张图自己的参数运行，不自动复制比例尺；重分割需确认并可撤销。

## 自动排版与手动调整

自动切出的每枚可分别勾选、独立裁剪与排版。关闭自动切分时仍可按组合保留。

顶部“图版排版” → 选择参与照片 → “载入已确认对象” → 自动转正与原始尺寸联合排版。可以拖动、旋转、缩放、编辑标签、移除对象、撤销或重新自动排列。裁剪背景透明，版面按黑底/白底逐页导出2400×1800 PNG。

“保存项目”同时包含可编辑版面；也可单独保存或打开版面JSON。PNG不能恢复编辑。版面是加载时的快照，mask、校准或确认状态改变时明确提示来源过期，不静默替换手动布局。重新载入会重新排版，可撤销。向已有项目合并图像时保留现有版面，避免覆盖；恢复文件中的完整布局请在空工作台打开项目。

“自动排版”恢复原始尺寸比例并重新摆放；手动移动和角度可继续编辑，单枚缩放后显示独立标尺。支持Shift多选、对齐、等距、网格吸附和方向键微调。接触组合仍为一个排版对象。整套最多200对象、2500万裁剪像素，独立JSON上限50 MB。物理标尺依赖可靠尺度校准，不推测实际尺寸。旧版已单独缩放的布局需点击“自动排版”才恢复原始尺寸关系。

## 0.4参数选择的范围

75次正式参数评估（74个不同组合）：先68次粗搜，再7次局部细搜。调参集为5张照片中的20个连通对象，以临时视觉数量参考和两组内部点为依据；0.30/0.25在该网格得分最佳，但内核比例存在并列最优，没有唯一全局最优。

参数冻结后在另外5张照片中的14个对象检查，12个数量符合临时参考；Image016对象2漏切、对象5天然多叶误切。Image026指定接触组合切成4枚。参考由助手视觉判读，未经过专家确认，不能当作像素边界金标准或物种/标本外部验证。同目录照片可能相关，结果不代表通用准确率。完整30张前后对比、失败案例、参数与数据记录见同级MR0145-autosplit-test。

同一批测输入重复运行结果逐像素一致，所有切分前景并集保持不变；这验证实现一致性，不证明生物学边界正确。不同JPEG解码路径可产生少量阈值像素差异：Image026批测与Chrome的组合面积相差5 px，GUI验证用同一解码路径前后对照。

筛选仍可能漏掉小型或低对比骨针。保留原图、参数和quality-audit.json，科研分析须检查选择偏差。提示只是形状特征，并不证明接触、遮挡或完整；不能将候选连通对象数当作单枚骨针丰度。

## 测量含义

| 字段                             | 定义与限制                                                           |
| -------------------------------- | -------------------------------------------------------------------- |
| area                             | mask像素数；校准后乘以μm/px的平方                                    |
| perimeter                        | 二值mask的marching-squares近似周长；边缘清晰度、阈值和分辨率会影响它 |
| max_feret_length                 | 像素单元外边界凸包的最大Feret径；不是沿弯曲骨针的弧长                |
| width_perpendicular_to_max_feret | 在最大Feret方向的垂直方向上的投影宽度；不是最小Feret径或平均体宽     |
| aspect_ratio                     | 上述长度除以上述宽度                                                 |
| circularity                      | min(1, 4πA/P²)，离散小对象可能因截断失去区分度                       |
| bbox_*_px                        | 原工作图像中的像素包围盒；即使校准后仍以px记录                       |

CSV的`unit`按图分别为`px`或`um`；面积使用对应平方单位。图像ID、标本编号、组织、实例ID、人工形态备注、合成数据标记一起保存。实例ID用于当前项目内对应，**重新分割可能改变ID**。

所有测量描述的是二维可见投影。切开工具会删除切线上的少量像素，不会重建重叠处真实轮廓；分离碎片被合并后，会作为同一对象测量。请保留原图并进行科研复核。

## 输入与项目格式

- 每张最多1200万像素、输入文件最多80 MB；不自动缩小原图。
- 每个工作空间最多30张图；建议大图分成小批处理。项目导入ZIP上限300 MB。
- 单页TIFF经UTIF解码为8位RGBA工作图；TIFF原文件原样保存在项目里。支持的压缩/像素格式受解码器限制；不能用于原始16位光强定量。多页TIFF需先导出单张合焦图。
- PNG/JPEG为主要验证格式；其他由系统WebView解码的图像格式不是第一版的保证范围。
- `project.json`记录尺寸、名称、参数、阈值、校准、标本信息及文件对应关系。
- `images/<image_id>/original`为未改动输入文件，原文件名和类型见清单；无扩展名不是数据转换。
- `labels.u32`按行存储小端32位实例编号，0为背景。每个实例另有crop/mask/cutout PNG，位于`objects/`。
- `foreground-mask.png`是整图前景二值图，不包含独立实例ID；实例关系应读`labels.u32`。
- 项目保留当前mask与备注，不保存撤销历史。

## 技术栈

**Tauri 2 + React 19 + TypeScript 7 + Vite 8 + Rust ONNX Runtime。**分割继续在 Web Worker 中执行，分类在原生后台线程执行；不增加服务器、数据库或大型状态管理库。版本锁定在 `package-lock.json`、`Cargo.lock` 和 `src-tauri/models/encoder.json`。

| 层       | 选择                    | 用途                                   |
| -------- | ----------------------- | -------------------------------------- |
| 桌面壳   | Tauri 2 / Rust          | Windows和macOS原生窗口、文件保存与打包 |
| 界面     | React 19 / TypeScript 7 | 中文交互、可编辑实例、参数和项目状态   |
| 开发构建 | Vite 8                  | 本地开发及前端生产构建                 |
| 图像显示 | Canvas 2D + SVG         | 原图、mask、实例编号与校准线           |
| 图像处理 | TypeScript / Web Worker | 无GPU依赖的传统分割及二维形态测量      |
| 文件     | UTIF / JSZip            | 单页TIFF、项目归档和结果导出           |
| 验证     | Vitest / Playwright     | 数值夹具、完整界面流程测试             |

Rust 负责分类输入预处理、冻结编码器、特征缓存、分类层训练和模型包校验。原来的分割和二维形态测量实现不变。模型导出脚本只供开发端使用。

官方资料：[Tauri 2架构](https://v2.tauri.app/concept/architecture/)、[React](https://react.dev/)、[Vite](https://vite.dev/)、[Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API)。

## 开发与构建

需要Node.js 22.12+及npm；桌面构建另需Rust stable及[Tauri平台依赖](https://v2.tauri.app/start/prerequisites/)。macOS需Xcode Command Line Tools；Windows需C++构建工具及WebView2。

```sh
npm ci
npm test
npm run dev
```

浏览器开发地址是`http://127.0.0.1:1420`。桌面开发或打包：

```sh
npm run desktop:dev
npm run desktop:build
```

Mac 仅生成 `.app` 可使用 `npm run desktop:build -- --bundles app`。构建结果位于 `src-tauri/target/release/bundle/`。当前随附原生库为 Apple Silicon；不支持直接用这份库构建 Intel Mac。Windows / Apple Silicon 的手动 CI 配置尚未在云端执行。

界面冒烟测试需要本机Chrome及已运行的开发服务器：

```sh
node tests/ui.smoke.mjs
```

本次交付生成Apple Silicon Mac应用；Windows与Intel Mac仅提供相同源码及构建配置，未在那些平台实机验证。Mac应用未做Apple开发者签名和公证，不是App Store发行版。不要关闭系统安全保护；仅在确认来源后按macOS提示批准本地测试应用。
